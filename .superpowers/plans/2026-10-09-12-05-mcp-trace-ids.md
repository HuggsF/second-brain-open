# MCP Trace IDs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every call to the 15 MCP tools leaves one JSON line in `.runtime/trace-log.jsonl`, groupable by task, readable with `cli.py trace`.

**Architecture:** A pure module `core/tracing.py` (ids, redaction, append, rotation, read) and a FastMCP middleware `core/trace_middleware.py` that records each `call_tool`. Every server registers the middleware and every tool accepts an optional `task_id`. The SSH gateway emits child events through the same module and stops writing `gateway-audit.jsonl`.

**Tech Stack:** Python 3 (`.venv`), `fastmcp==4.0.11` (`fastmcp.server.middleware.Middleware`), `click`, `unittest`.

**Spec:** `.superpowers/specs/2026-10-09-11-56-mcp-trace-ids-design.md`

## Global Constraints

- Log file: `.runtime/trace-log.jsonl`, UTF-8, append only, one JSON object per line, `schema_version` 1.
- `trace_id`: 32 lowercase hex. `span_id`: 16 lowercase hex.
- `task_id` matching `^[0-9a-f]{32}$` is used as `trace_id`; any other non-empty text gives `trace_id = sha256(task_id.strip()).hexdigest()[:32]` and `task_label` = that text, control characters removed, at most 80 characters.
- Redacted keys (case-insensitive substring): `token`, `password`, `secret`, `key`, `authorization`, `credential` → value `[redacted]`. Other strings truncated to 200 characters; the `command` argument to 500. `task_id` is never copied into `args`.
- A record is bounded to 4096 bytes (truncate `args` first). Rotation at 5 MB (`5 * 1024 * 1024`), three rotated files kept (`trace-log.1.jsonl` … `trace-log.3.jsonl`).
- Tracing never makes a tool call fail; the tool result is returned unchanged.
- `caller` = `context.fastmcp_context.session.client_params.client_info.name`, else `"unknown"`.
- Run Python and tests from the repository root: `.\.venv\Scripts\python.exe -m unittest <module>`.
- Commit convention: Conventional Commits, one concern per commit.

## Review Focus

- `task_id` that is blank, only control characters, or not a string → treated as absent (fresh `trace_id`, no `task_label`).
- Arguments that are not JSON-serialisable (`bytes`, objects) or very large → record still written, within 4096 bytes.
- Log path that cannot be written (a directory where the file should be, or read-only) → tool call still succeeds.
- A tool that raises → the exception reaches the caller unchanged and exactly one `error` record exists.
- `cli.py trace` with an unknown or malformed id → message and exit code 1, no traceback.
