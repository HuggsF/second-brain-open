## Bug de dedup: INTEGER vs TEXT no SQLite — 17:00–17:05

### Causa raiz

A query de deduplicação do webhook (server.js:238) usava pedidoWebhook.id diretamente. O Bling envia id como NUMBER no JSON; o driver SQLite faz bind como sqlite3_bind_int64. A coluna erp_id é TEXT. No SQLite, INTEGER nunca é igual a TEXT, mesmo com valores idênticos (regra da seção 4.0 "Type Conversions Prior to Comparison"). Resultado: a dedup nunca encontrava pedido existente → todo webhook criava nova linha → nova etiqueta J&T.

O INSERT (linha 255) já usava String() desde setembro/2026 (fix do bug .0), mas a query de dedup ficou sem String().

### Impacto medido

- 44 pedidos com 2 tracking codes cada (de 24/09 a 08/10)
- Pico de 25 duplicados em 08/10
- Distribuição por dia: 24/09(1), 26/09(1), 29/09(2), 30/09(3), 01/10(8), 03/10(1), 06/10(7), 07/10(1), 08/10(25)

### Correção

Commit e60344d na branch fix/nota-fiscal-jt, pushado para origin. 32/32 testes aprovados. Deploy pendente.
